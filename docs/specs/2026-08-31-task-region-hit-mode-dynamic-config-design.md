# 算法任务区域命中模式动态配置实施设计

## 1. 目标

在现有“单视频流、多算法任务、多模型、任务级区域隔离”的基础上，将区域命中判定从固定逻辑升级为算法任务级动态配置：

- 同一视频流上的不同算法任务可独立选择区域命中模式和阈值。
- 运行中的任务可修改区域过滤配置，下一批事件即生效，不重启推理进程。
- 前端可选项来源于系统数据字典，管理员可控制新建配置时展示的选项。
- 已保存的旧配置继续可执行，不因字典停用或升级而失效。

## 2. 数据字典

新增字典类型 `ai_region_hit_mode`：

| 字典值 | 名称 | 判定规则 |
| --- | --- | --- |
| `center` | 中心点 | 检测框中心点位于任一区域内 |
| `bottom_center` | 底边中点 | 检测框底边中点位于任一区域内 |
| `any_intersection` | 任意交集 | 检测框与任一区域存在面积交集或边界接触 |
| `overlap_ratio` | 区域内面积达到阈值 | 检测框落入区域的面积 / 检测框面积不小于阈值 |
| `fully_inside` | 完全位于区域内 | 检测框全部位于任一区域内 |

`overlap_ratio` 的默认阈值为 `0.5`，页面以 `1% ~ 100%` 展示，接口与存储使用 `0.01 ~ 1.0`。

## 3. 配置模型

配置复用算法任务的 `post_pipeline`，不增加重复字段：

```json
[
  {
    "plugin": "region_gate",
    "enabled": true,
    "params": {
      "hit_mode": "overlap_ratio",
      "min_overlap_ratio": 0.5
    }
  },
  {
    "plugin": "default_pass",
    "enabled": true,
    "params": {}
  }
]
```

更新区域过滤时只合并 `region_gate` 步骤，保留任务已有的其他后处理步骤、顺序及失败策略。未显式配置时维持默认 `center`。

## 4. 运行链路

1. WEB 从系统数据字典读取可选模式，并在任务列表的“区域过滤”入口编辑。
2. WEB 调用算法任务更新接口，仅提交合并后的 `post_pipeline`。
3. VIDEO 校验命中模式和阈值，保存任务配置并递增 `template_revision`。
4. 若任务正在运行，VIDEO 立即向 POST 推送新模板。
5. POST 对模板做防御性校验并原子替换任务缓存；后续事件读取新模板。
6. RUNTIME 不承担区域事件过滤，因此无需重启或重载模型。

## 5. 几何实现

- 区域支持标准矩形及简单多边形，包括凹多边形。
- `overlap_ratio` 采用“多边形三角剖分 + 三角形对检测框裁剪”计算交集面积，分母固定为有效检测框面积，不使用 IoU。
- `any_intersection` 同时识别正面积交集和边界接触。
- `fully_inside` 使用交集面积比例接近 1 的判定，并使用统一浮点误差容限。
- 无效检测框或无效多边形不命中，不允许造成事件处理异常。

## 6. 兼容与异常策略

- 保留旧模式 `any_corner`、`any`、`all`、`bottom` 的既有执行语义，但不在新字典中展示。
- 字典项被停用只影响新选择；页面仍能显示和保留任务已经存储的值。
- VIDEO 拒绝未知新配置、非数值阈值及超出范围的阈值。
- POST 的 HTTP/MQTT 模板入口进行相同的防御性校验；非法热更新不覆盖当前有效缓存。
- 区域为空或当前检测模型没有适用区域时，沿用现有全画面放行策略。

## 7. 验收标准

- 五种模式在矩形、凸多边形、凹多边形和边界条件下均有自动化测试。
- 两个算法任务对同一检测框使用不同配置时，结果互不影响。
- 运行中更新后模板版本递增，POST 不重启即可按新规则过滤。
- 系统字典缺失时页面提供内置安全回退；字典停用不破坏已保存配置。
- VIDEO、POST、WEB 原有回归测试与构建全部通过。
