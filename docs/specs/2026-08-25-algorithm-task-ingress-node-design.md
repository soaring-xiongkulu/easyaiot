# 算法任务接入节点联动设计

## 目标

创建或编辑算法任务时，根据摄像头登记时保存的 `ingress_node_id` 自动约束算法执行节点，避免任务被调度到无法访问摄像头的节点。

## 交互规则

- 关联摄像头位于调度配置之前，摄像头选项展示主节点或边缘接入节点。
- 选择边缘接入摄像头后，调度策略自动设为“指定节点”，目标节点自动设为该摄像头的接入节点。
- 同一算法任务仅允许选择接入节点相同的摄像头；禁止边缘节点之间混选，也禁止主节点和边缘节点设备混选。
- 接入节点离线、已删除或不具备“视频分析”能力时，对应摄像头不可用于新任务，并显示可操作的原因提示。
- 主节点接入摄像头继续支持原有本机、自动调度和指定节点策略。
- 历史任务可以查看；编辑保存时按新规则校验。

## 服务端约束

- 创建和更新接口根据最终设备列表及最终调度字段统一校验。
- 边缘接入设备要求 `schedule_policy=node`，且 `target_node_id` 必须等于唯一的 `ingress_node_id`。
- 不同接入节点的设备同时出现时拒绝保存，并提示按接入节点拆分算法任务。
- 不新增数据库字段，不改变现有 API 数据结构。

## 验收标准

1. 单个或多个同节点边缘摄像头会自动选择正确节点。
2. 不同接入节点的摄像头无法混选，直接调用接口也无法保存。
3. 离线、已删除或无视频分析能力的接入节点有明确提示。
4. 主节点接入设备保持现有调度能力。
5. 查看历史任务不受影响，编辑不一致的历史任务时必须先修正。
