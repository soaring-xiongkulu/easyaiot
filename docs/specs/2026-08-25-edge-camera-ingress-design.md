# 边缘节点摄像头接入设计

## 目标

硬件摄像头和 NVR 在添加时可以选择主节点或在线边缘节点作为接入节点。摄像头只需与所选边缘节点互通；边缘节点负责发现、扫描、验证及拉流，并主动将视频流发布到主节点媒体服务，供主节点统一查看和消费。

覆盖以下硬件接入方式：

- IPC：ONVIF 发现、跨网段扫描、手动 RTSP。
- NVR：跨网段扫描、手动登记、通道枚举与批量挂载。
- 已登记 IPC/NVR：允许显式修改接入节点。

国标和 RTC 平台接入不在本次范围内。

## 数据模型

- `device.ingress_node_id`：关联 iot-node 的 `compute_node.id`；空值表示主节点本机。
- `nvr.ingress_node_id`：NVR 及其通道的统一接入节点；修改时同步到下挂设备。
- `stream_forward_task.publish_scope`：`node` 表示发布到执行节点媒体服务，`control_plane` 表示发布到主节点媒体服务。

不建立跨服务数据库外键。老库在 VIDEO 启动时幂等补列和索引。

## 调用与数据流

```text
浏览器
  -> VIDEO 控制面
      -> iot-node 摄像头代理 API
          -> 所选边缘节点 Sentinel Agent
              -> 摄像头 / NVR（发现、扫描、验证、枚举）

摄像头 / NVR RTSP
  -> 所选边缘节点推流任务（拉流）
      -> 主节点 SRS（RTMP 发布）
          -> 主节点统一 HTTP-FLV / RTMP 播放地址
```

边缘节点 Agent 提供经令牌保护的轻量接口：

- `discover`
- `scan-segment`
- `probe-onvif`
- `probe-stream`
- `nvr-channels`

iot-node 校验节点存在且在线，按需同步 VIDEO 扫描模块，然后代理请求到 Agent。凭证只用于本次节点侧访问；ONVIF 探测结果不回传密码。

## 调度规则

- 主节点接入：沿用原本的本机/自动调度和节点本地发布行为。
- 边缘节点接入：推流任务固定使用 `schedule_policy=node`、`target_node_id=ingress_node_id`、`publish_scope=control_plane`。
- 边缘任务的输入仍为摄像头原始地址，输出强制指向主节点 SRS。
- 部署记录同时保留执行节点 `host` 和媒体发布节点 `publish_host`；播放地址以 `publish_host` 为准。
- 节点离线时不自动切换到其他节点，避免在无摄像头网络可达性的节点上反复失败。

## 交互

- “添加设备”页在 IPC/NVR 方法上方提供统一接入节点选择器，默认“本机（主节点）”。
- 仅列出在线且启用、具有 `computeNodeId` 的边缘节点。
- 切换节点后清空当前扫描结果，后续扫描、验证、登记使用新节点。
- 设备列表展示接入节点及在线状态。
- IPC/NVR 编辑弹窗支持显式重新绑定；NVR 重新绑定会同步全部下挂通道并重启对应转发部署。

## 失败处理

- 节点离线、Agent 不可达、扫描模块同步失败或源流不可读时，登记/重新绑定失败并返回明确错误。
- 已登记任务在节点离线后保留绑定，不做无意义的自动故障转移；节点恢复后由原绑定继续运行。
- 控制面无法解析可供边缘访问的主节点地址时，拒绝下发 `control_plane` 发布任务。

## 验收标准

1. 选择边缘节点后，ONVIF、网段扫描、RTSP 验证和 NVR 通道枚举均在该节点执行。
2. 登记结果持久化正确的 `ingress_node_id`，NVR 通道与 NVR 保持一致。
3. 自动创建的转发任务固定运行在所选节点，并推流到主节点 SRS。
4. 播放地址始终指向主节点，而不是摄像头私网或边缘节点地址。
5. 编辑接入节点后，正在运行的转发任务执行一次完整重启并更新部署绑定。
6. 主节点接入和既有未绑定数据保持兼容。
