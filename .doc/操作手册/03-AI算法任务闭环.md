# 03 · AI 算法任务闭环

## 目标

从模型就绪 → 创建算法任务 → 检出命中 → **告警事件**可查、可取证（抓拍/录像）。

这是平台最核心的「智视」闭环。

---

## 前置条件

- 至少 1 路摄像头已按 [视频设备接入](./02-视频设备接入.md) 在线可播
- AI / 训练相关服务可用；建议 RUNTIME 已部署（默认低时延 `executor=cpp`）
- 若需告警外发，先完成 [通知渠道底座](./01-登录与基础准备.md#操作链-a4通知渠道底座告警外发前必做)

---

## 操作链总览

```text
数据标注 / 选用内置模型 → 模型训练或导入 →（可选）人脸库/车牌库
        ↓
流媒体管理 · 算法任务 · 新建 → 绑摄像头与模型 → 配区域/时段/通知
        ↓
启动任务 → 分屏看带框流 / 抓拍空间看图 → 告警事件处置
```

---

## 操作链 C1：模型与标注准备

> 若直接使用平台内置/已部署模型，可跳过标注与训练，从 C2 开始。

| 步骤 | 菜单路径 | 做什么 |
|------|----------|--------|
| 1 | **数据标注**（`/dataset`） | 建数据集；导入图片/视频或 YOLO/COCO 等格式；完成标注（可用 SAM 辅助） |
| 2 | **模型训练 / 模型管理**（`/train/index`） | 建训练任务；查看模型；导出/部署；按需做模型推理验证 |
| 3 | （可选）**流媒体管理 → 人脸库 / 车牌库** | 维护比对库，供任务开启人脸/车牌匹配 |

**验收：** 有可用模型（推理测试通过）；比对库可检索（若启用）。

---

## 操作链 C2：创建并运行算法任务

| 步骤 | 操作 |
|------|------|
| 1 | **流媒体管理 → 算法任务 → 新建算法任务** |
| 2 | 选择任务类型： |
| | · **实时**：持续分析视频流 |
| | · **事件抓拍 / 抓拍**：按事件或计划分析抓拍图 |
| | · **周期巡检**：多路轮巡，少连接广覆盖 |
| 3 | 选择执行方式：优先低时延（cpp / RUNTIME），或全功能 python 兼容路径 |
| 4 | 关联摄像头（直连 / NVR 通道 / 国标通道等）与模型 |
| 5 | 配置告警：告警事件类型、触发标签、告警间隔；按需开人脸/车牌匹配、AI 后处理 |
| 6 | 配置布防时段（全天 / 自定义）、通知渠道（引用已配好的模板） |
| 7 | 在任务上配置 **检测区域**（在抓拍图上画多边形/四边形） |
| 8 | **启动**任务 |

**验收：**

- 任务状态为运行中
- 有处理帧 / 检测计数（以界面为准）
- **分屏监控** 勾选「启用 AI」可看到带框流（实时类）
- 抓拍类可在 **存储空间 → 抓拍空间** 看到图片

---

## 操作链 C3：告警处置与取证

| 步骤 | 菜单路径 | 做什么 |
|------|----------|--------|
| 1 | **告警事件** | 在「告警事件」列表查看新事件 |
| 2 | （可选）Tab **地图分布** | 按坐标、时间、类型筛选 |
| 3 | 打开事件详情 | 看设备、时间、对象、抓拍图 |
| 4 | 播放/下载告警录像 | 有录像的事件可回放取证 |

**验收：** 事件记录完整；图片可看；录像可播（纯抓拍无录像场景除外）。

---

## 精准告警要点（降低误报）

平台常用「三重条件」：

1. **检测区域**内  
2. 处于 **布防时段**  
3. 命中配置的 **告警事件 / 标签**

三者同时满足才告警。调参时优先收紧区域与标签，而不是一味降模型阈值。

## 本链结束检查

- [ ] 算法任务运行中
- [ ] 能复现至少 1 条告警事件（含证据图）
- [ ] （可选）通知已触达 → 继续 [告警通知与对外联动](./05-告警通知与对外联动.md)
