# 05 · 告警通知与对外联动

## 目标

把平台内已产生的告警 / 业务事件，送达人（通知）或外部系统（TRANSFORM）。

---

## 前置条件

- 已有告警来源：通常来自 [AI 算法任务](./03-AI算法任务闭环.md) 或 IoT 规则/事件
- 通知外发：已完成 [通知渠道底座](./01-登录与基础准备.md#操作链-a4通知渠道底座告警外发前必做)
- TRANSFORM：TRANSFORM 服务与 Kafka 等依赖可用（默认管理端口常见为 `48096`）

---

## 操作链 E1：告警 → 通知人

```text
算法任务命中（区域+时段+标签）
    → 告警落库（告警事件）
    → 按任务绑定的通知渠道推送
    → 通知管理 · 推送历史 核对
```

| 步骤 | 操作 |
|------|------|
| 1 | 在算法任务中启用告警事件，并绑定已配置的通知渠道/模板 |
| 2 | 触发一次真实检出或测试场景 |
| 3 | **告警事件** 确认有新记录与证据图 |
| 4 | **通知管理 → 推送历史** 确认渠道成功 |

**验收：** 告警时间与推送时间线一致；接收端（企微/钉钉/邮件等）收到内容；失败记录可据此改模板或渠道。

---

## 操作链 E2：告警 / 业务事件 → TRANSFORM 对外转发

适用：要把设备消息、告警、人脸匹配等投递到 MES / ERP / CRM / WMS / Webhook。

**主入口：** 侧栏 **数据转发**（`/transform/index`）

常见 Tab：运行集群 → 转发规则 → 数据目的 → 映射模板 → 投递监控

| 步骤 | 操作 |
|------|------|
| 1 | **运行集群**：确认实例心跳正常 |
| 2 | **数据目的**：登记外部系统（Party）连接信息 |
| 3 | **映射模板**：约定字段映射（Contract / Mapping） |
| 4 | **转发规则**：绑定源 Topic/事件 → 目的与模板 |
| 5 | **投递监控**：观察成功/失败与 Trace |
| 6 | （联调）可按仓库内 `TRANSFORM/docs/操作手册.md` 跑脚本验收 |

**验收：** 集群心跳正常；投递监控显示成功；目标系统收到预期报文。

---

## 值守日常：告警处置节奏

| 顺序 | 动作 |
|------|------|
| 1 | **告警事件** 列表或地图筛选「未处理」 |
| 2 | 看抓拍 / 录像，判断真警或误报 |
| 3 | 按现场制度闭环（确认、派单、忽略等，以界面状态为准） |
| 4 | 误报多：回 [算法任务](./03-AI算法任务闭环.md) 收紧区域、标签、布防时段 |

---

## 本链结束检查

- [ ] 告警事件可查可证
- [ ] （对人）推送历史成功
- [ ] （对系统）TRANSFORM 投递成功
