| 项目 | 说明 |
|------|------|
| 文档版本 | v1.3 |
| 状态 | 专项设计（从属于 POST 模块） |

| 目标 | 区域检测真正生效；不进推理热路径；**几何唯一实现**；与人流等后处理同一套插件标准 |

## 1. 背景与目标

### 1.1 产品承诺

操作手册「三重条件」约定：目标同时满足以下条件才产生告警：

1. 落在 **检测区域**内  
2. 处于 **布防时段**  
3. 命中配置的 **告警事件 / 标签**

当前仅第 2、3 项在部分链路可靠；第 1 项配置链完整，但几何过滤经常未真正生效，且分散在 RUNTIME / Python /（缺失的）sink 多处，语义不一致。

### 1.2 设计目标

| # | 目标 | 度量 |
|---|------|------|
| G1 | 配了启用区域后，区域外目标**不落告警** | 集成测试：区外检出 → 无告警记录 |
| G2 | 未配区域 / 区域全部禁用 → 行为等同「全画面」 | 兼容现有任务 |
| G3 | **不影响算法性能**：不裁剪输入、不改模型、不进 GPU/ORT 前向 | 推理耗时对比无明显回退 |
| G4 | `executor=cpp` / `python`；`realtime` / `snap` / `patrol`；`standard` / `full` / `mini` / `edge` **同一套判定结果** | 部署矩阵验收 + 黄金用例对齐 |
| G5 | 告警落库写入**实际命中区域名** | `alert.region` 准确 |
| G6 | 预览叠加流可画全量框 + 区域轮廓；区域只约束**告警**，不约束推理 | 分屏「启用 AI」体验不变 |
| **G7** | **区域几何逻辑有且仅有一处实现（统一收口）** | 代码检索：RUNTIME / iot-sink **无**告警用 point-in-polygon |

### 1.3 非目标（本期不做）

- 按区域切换 / 加载不同模型权重（`model_ids` 本期只做「区域是否对当前任务生效」）
- 绊线穿越状态机（`region_type=line`）完整轨迹分析（见 §9 分期）
- 运行中热更新区域而不重启任务（可列为二期）
- 改变用户自定义 `post_process.py` 契约（仅保证其入参已过统一 Gate）

### 1.4 硬约束：统一收口（本版相对 v1.0 的关键修正）

> **禁止**「cpp 一套 + Python 一套 + sink 再兜底一套」的多实现 / 多挂载几何逻辑。  
> 部署形态只允许差异化 **传输与落库通道**，不允许差异化 **区域是否命中** 的判定代码。

| 允许 | 禁止 |
|------|------|
| 唯一实现：`VIDEO` 内 `RegionGate` | RUNTIME 内对告警做 `_isInAlarmRegion` / `pointInRegions` |
| 执行器只上报「告警候选」（可含全量检出） | iot-sink 内再写一套 Ray Casting / 点面判断 |
| 各 Profile 在 Gate **之后** 分叉发 MQTT / 直连落库 | mini 走 A 逻辑、standard 走 B 逻辑 |
| OSD 画区域多边形轮廓（纯展示） | OSD/告警两套不同命中规则且都自称「区域检测」 |

## 2. 现状与根因

### 2.1 现有流水线（问题形态）

```text
WEB 绘制 → device_detection_region
              ↓
     VIDEO 写 ini [regions] ──┐
                              ▼
RUNTIME：本地 pointInPolygon（易因坐标格式失效）──► MQTT ──► iot-sink（只布防）
Python：无区域过滤 ─────────────────────────────────► 直连/MQTT
后处理 Worker：ctx 带 regions，无默认几何过滤
```

结果：同一产品能力在不同部署 / 执行器上行为分裂，且 cpp 路径还常因格式问题退化为全画面。

### 2.2 关键缺口（摘要）

| ID | 缺口 |
|----|------|
| A | DB `{x,y}` vs RUNTIME `[[x,y]]` 不兼容 → 区域加载失败 → 全画面 |
| B | Python 路径无 ROI |
| C | 几何逻辑分散 / 缺失，无统一收口 |
| D | snap/patrol 多设备区域串扰 |
| E | 告警 region 名不准确 |
| F | `model_ids` 未进入过滤语义 |
| G | 与用户后处理脱节 |

### 2.3 性能结论

区域判定是推理之后的 CPU 微操作。性能红线是：**禁止裁剪推理 / GPU mask**；**不要求**把几何塞进执行器本地「为了快」——统一收到 VIDEO 后处理闸门，相对 YOLO 可忽略，且换来全区署一致。

## 3. 总体设计：单一收口

### 3.1 一句话

**所有执行器只产出「告警候选」；所有部署形态的区域判定，只在 VIDEO 的 `AlertCandidateIngest` 内调用唯一的 `RegionGate`；Gate 之后再按 Profile 分发落库 / 通知。**

### 3.2 目标架构

```text
        ┌─ RUNTIME(cpp)  realtime/snap/patrol ─┐
        │    全图推理 → 全量检出                 │
        │    （不做告警区域几何判定）              │
        ├─ Python executor  realtime/snap/patrol┤
        │    全图推理 → 全量检出                 │
        └──────────────────────────────────────┘
                          │
                          │  告警候选 AlertCandidate
                          │  （device_id / detections / image / task 元数据）
                          ▼
        ╔══════════════════════════════════════╗
        ║  VIDEO · AlertCandidateIngest         ║
        ║  ★ 全区署唯一收口                      ║
        ║                                      ║
        ║  1. alert_class_names 过滤（可选）     ║
        ║  2. RegionGate（唯一几何实现）         ║
        ║  3. 标记 region_filter=applied|bypass ║
        ║  4. 告警间隔 / 冷却（若放此处）         ║
        ╚══════════════════════════════════════╝
                          │
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
     mini / edge     standard / full   可选异步后处理
     本进程直连落库    发 MQTT/Kafka     enqueue Worker
     + 本地通知路径    → iot-sink        （入参已是 Gate 后）
                       只做：布防时段
                            落库 / MinIO
                            通知下发
                       ★ 禁止再做几何
```

### 3.3 核心原则

1. **推理全图、告警分区**：模型看完整帧；区域只决定候选能否成为告警。  
2. **RegionGate = 平台内置后处理**：与 `post_process_enabled` 无关；有启用区域即判定。  
3. **逻辑单例、通道多态**：几何代码一处；MQTT / 直连 / Kafka 只是 Gate 后的运输。  
4. **空区域 = 全画面 bypass**：`region_filter=bypass`，`region=全画面`。  
5. **执行器零告警几何**：RUNTIME / Python 执行器**删除或停用**告警路径上的 point-in-polygon；避免第二套逻辑。  
6. **iot-sink 零告警几何**：只信任 VIDEO 已标记的候选；只做布防与存储通知。

### 3.4 与用户 AI 后处理的关系

| 能力 | 实现位置 | 异步？ | 几何？ |
|------|----------|--------|--------|
| **RegionGate** | **仅 VIDEO Ingest** | 同步 | **是（唯一）** |
| alert_class | VIDEO Ingest（与 Gate 同层） | 同步 | 否 |
| 布防时段 | iot-sink（或 mini 等价校验若已有） | 同步 | 否 |
| 姿态 / 意图 / `post_process.py` | Worker | 异步 | **否**；只消费 Gate 后数据 |

姿态意图里若仍需「人是否在区域内」，**必须调用同一 `region_gate` API**，禁止再手写一套 `_person_in_regions` 分叉实现（现有函数改为 thin wrapper）。

## 4. 为何收口必须在 VIDEO

| 模块 | 是否出现在全部部署形态 | 结论 |
|------|------------------------|------|
| RUNTIME(cpp) | 否（可只用 python） | 不能作为唯一实现 |
| iot-sink | 否（mini/edge 常无） | 不能作为唯一实现 |
| **VIDEO** | **是（编排 + 告警/任务中枢）** | **唯一合理收口** |

因此：即使 standard 最终由 sink 写库，**区域判定也必须先经过 VIDEO**；sink 不得复制几何。

## 5. 几何与数据契约（唯一定义）

### 5.1 事实源

表：`device_detection_region`。Ingest 只按 **当前候选的 `device_id`** 加载 `is_enabled=true` 的区域。

### 5.2 Canonical points

```json
{
  "id": 12,
  "device_id": "cam_001",
  "region_name": "东门禁区",
  "region_type": "polygon",
  "points": [[0.12, 0.20], [0.55, 0.20], [0.55, 0.80], [0.12, 0.80]],
  "model_ids": [1, 3],
  "is_enabled": true
}
```

- 读库：`{x,y}` → `[x,y]`。  
- **不再依赖** RUNTIME ini `[regions]` 做告警判定（ini 区域段可逐步废弃，或仅供 OSD 画轮廓）。  
- 判定：点均在 `[0,1]` 则按帧宽高（或告警图宽高）缩放；否则视像素。

### 5.3 命中算法（只在 `region_gate.py`）

```text
cx, cy = bbox 中心
命中 ⇔ ∃ region ∈ Regions(device_id):
         启用 ∧ model_ids 约束通过
         ∧ type ∈ {polygon, rectangle}
         ∧ pointInPolygon(cx, cy, scaled_points)
```

- 空列表 → bypass，`全画面`。  
- 多命中 → `sort_order` 最小者写入 `alert.region`；`matched_regions` 可列全部。  
- 默认 `region_hit_mode=center`。

### 5.4 `model_ids`

- 空：对该设备所有任务生效。  
- 非空：与任务 `model_ids` 有交集才参与 Gate。  
- 不在推理期切模型。

### 5.5 候选 / 告警 Payload

**执行器 → Ingest（候选，未 Gate）：**

```json
{
  "device_id": "cam_001",
  "device_name": "...",
  "task_id": 100,
  "task_type": "realtime",
  "detections": [ { "bbox": [x1,y1,x2,y2], "class_name": "...", "confidence": 0.9 } ],
  "image_path": "...",
  "frame_width": 1920,
  "frame_height": 1080,
  "time": "..."
}
```

**Ingest → 下游（已 Gate）：**

```json
{
  "region": "东门禁区",
  "information": {
    "region": "东门禁区",
    "matched_regions": ["东门禁区"],
    "region_filter": "applied",
    "region_gate_version": "1",
    "detections_before_region": 5,
    "detections_after_region": 2
  },
  "detections": [ /* 仅命中子集 */ ]
}
```

`region_filter` 取值：

| 值 | 含义 |
|----|------|
| `applied` | 已跑唯一 Gate，且存在启用区域 |
| `bypass` | 无启用区域，全画面 |
| `disabled` | 全局/任务关闭 Gate（应急） |

iot-sink：**不解析几何**；可校验若设备有启用区域但 `region_filter` 缺失 → 打告警日志 / 拒绝写入（严格模式，可配置），用于防止有人绕过 Ingest 直推。

## 6. 模块职责（收口后）

### 6.1 VIDEO（唯一逻辑所有者）

| 组件 | 职责 |
|------|------|
| `app/utils/region_gate.py` | **唯一** normalize + pointInPolygon + filter API |
| `app/services/alert_candidate_ingest_service.py`（新） | 统一入口：收候选 → class 过滤 → RegionGate → 分发 |
| 现有 `alert_hook_service` | 收敛为 Ingest 的运输适配 / 或内部转调 Ingest |
| `post_process_runner` | enqueue 前若尚未经 Ingest，必须先走 Ingest；Worker 内禁止第二套 Gate |
| `pose_intent_*` | 复用 `region_gate`，删除独立多边形实现 |

对外入口建议（二选一或并存适配期）：

1. **HTTP**：`POST /video/alert/candidate`（内部/执行器专用）  
2. **进程内**：Python 执行器直接 `ingest_alert_candidate(...)`  
3. **MQTT 适配**：若 cpp 暂仍发 MQTT，由 **VIDEO 侧消费者** 先收、Gate 后再转交 sink（见 §7）——**不是** sink 先落库。

### 6.2 RUNTIME（执行器，不做告警区域判定）

| 做 | 不做 |
|----|------|
| 全图推理、画全量框 | `_isInAlarmRegion` 决定是否告警 |
| 上报**全部**达置信度阈值的检出为候选 | `pointInRegions` 过滤 alarmDetections |
| 可选：OSD 绘制区域多边形轮廓（只画线，不算命中） | 维护告警用 regions 命中逻辑 |
| 通过 HTTP 候选入口或「原始候选 MQTT」发给 VIDEO | 直接发「已是最终告警」且假装已区域过滤 |

迁移期：删除 / 停用 Pipeline/Detech/Snap/Patrol 中告警路径的区域过滤；ini `[regions]` 不再作为告警依据（可留作 OSD 顶点源，或改为从同 DB 导出仅绘轮廓）。

### 6.3 iot-sink（通道后端，不做几何）

| 做 | 不做 |
|----|------|
| 布防时段 | Ray Casting / 点面判断 |
| 落库、MinIO、通知 | 再实现一套 RegionGate |
| 可选：拒绝无 `region_filter` 的脏消息 | 按 detections 自行过滤区域 |

### 6.4 WEB

- 绘制存储格式可维持 `{x,y}`。  
- 文案：区域只过滤告警；全区署同一套后处理逻辑。

## 7. 部署形态：只分叉通道，不分叉逻辑

```text
                  AlertCandidate
                        │
                        ▼
              VIDEO RegionGate（唯一）
                        │
         ┌──────────────┼──────────────┐
         │              │              │
    Profile=mini    Profile=edge   Profile=standard/full
         │              │              │
         ▼              ▼              ▼
   VIDEO 直连落库   VIDEO 直连落库   发布「已 Gate 告警」
   （弱化 MinIO）   （无 sink）      → MQTT/Kafka
                                         │
                                         ▼
                                      iot-sink
                                   布防 → 落库/通知
```

| Profile | 执行器如何交候选 | Gate 在哪 | Gate 后干什么 |
|---------|------------------|-----------|----------------|
| **mini** | Python 进程内 / cpp→HTTP 候选 | **VIDEO** | 直连 persist |
| **edge** | 同 mini | **VIDEO** | 直连 persist |
| **standard/full** | cpp/python → VIDEO Ingest（HTTP 或 VIDEO 消费候选主题） | **VIDEO** | 再发 sink 主题 |
| **cluster** | 工作节点执行器 → 中心 VIDEO Ingest（或同集群 VIDEO） | **VIDEO** | 按中心 Profile 分发 |
| **executor=cpp** | 只发候选，不本地 Gate | **VIDEO** | 同上 |
| **executor=python** | `ingest_alert_candidate()` | **VIDEO** | 同上 |
| **forward** | 无 AI | N/A | N/A |

### 7.1 standard 路径改造要点（避免两套逻辑）

**错误（禁止）：**

```text
cpp 本地 Gate → MQTT → sink 落库
python 另一套 Gate → …
sink 再 Gate 兜底
```

**正确：**

```text
cpp/python → 候选 → VIDEO RegionGate →（已过滤告警）→ MQTT → sink 布防+落库
```

适配期若 cpp 仍发 `mqtt/iot-alert-notification`：

1. **短期**：将该主题改为 VIDEO 消费（或桥接服务），Gate 后改发 `mqtt/iot-alert-gated` 给 sink；或  
2. **推荐**：cpp 改为 HTTP `/video/alert/candidate`，与 Python 对齐，MQTT 只承载 Gate 后消息。

### 7.2 一致性原则（验收用语）

> 任意 Profile × 任意 executor：同一 `device_id` + 同一 `detections` + 同一区域配置 → **相同的 kept/drop 与 region 名**。  
> 实现上只能有一份 `region_gate.filter_detections_by_regions` 决定该结果。

## 8. 详细流程

### 8.1 实时（任意 executor）

```text
Infer:
  dets = YOLO(full_frame)           # 无区域
  draw all boxes + optional region outlines
  submit AlertCandidate(device, dets, image_meta)

VIDEO Ingest:
  dets2 = filter_alert_class(dets)
  result = region_gate.filter(dets2, regions[device], ...)
  if result.kept empty: drop
  else: dispatch_by_profile(alert_with_region)
```

### 8.2 抓拍 / 巡检

- 候选必须带**当前** `device_id`。  
- Ingest 只加载该设备区域 → 自然消除多设备串扰（不再用「整份 ini 并集」）。

### 8.3 无区域 / 关闭 Gate

```text
无启用区域 → bypass → region=全画面 → 照常分发
REGION_GATE_ENABLED=false → disabled → 行为同升级前「不过滤」应急态
```

### 8.4 异步后处理

```text
仅当业务需要姿态/脚本时：
  Ingest 可在 Gate 通过后 enqueue；
  ctx.detections = kept；ctx.regions = 规范化区域列表；
  Worker 不得再次「决定是否区域告警」。
```

## 9. 分期落地

### Phase 0 —— 唯一库 + 契约

- [ ] 落地 `region_gate.py` + 单测（唯一几何实现）

- [ ] 明确禁止清单写入开发注释 / Code Review 清单  

### Phase 1 —— 全区署切到统一收口（核心）

- [ ] Python 实时/抓拍/巡检：告警改为只交候选 / 调 Ingest

- [ ] 删除 RUNTIME 告警用 regions 死代码；ini `[regions]` 降级或仅 OSD  
- [ ] `model_ids` 语义接入唯一 Gate  
- [ ] pose 路径复用 `region_gate`  
- [ ] 指标：仅在 VIDEO 打点 `region_gate_pass/drop`  

### Phase 3 —— 增强

- [ ] `line` 绊线（仍只加在 `region_gate.py`）  
- [ ] `iou_min` 等 hit_mode  
- [ ] 区域配置热更新（Ingest 侧缓存失效即可，执行器无感）

## 10. 配置

| 项 | 默认 | 说明 |
|----|------|------|
| `REGION_GATE_ENABLED` | `true` | 总开关（仅作用于唯一 Gate） |
| `region_hit_mode` | `center` | 仅 Ingest/Gate 读取 |
| `ALERT_INGEST_STRICT_REGION_FILTER` | `false` | sink/旁路：缺 `region_filter` 时是否拒绝 |

**不再**需要 RUNTIME ini `region_gate_enabled` 作为第二套开关（避免双开关漂移）；若留字段，只能表示「是否画区域轮廓」。

## 11. 性能

| 项 | 预期 |
|----|------|
| 模型前向 | 无影响 |
| 候选上报 VIDEO | 增加一次本机 HTTP/进程内调用；相对推理可忽略；图仍可走现有路径 |
| Gate CPU | 微秒级 |
| 禁止 | 每区域多次推理；sink/cpp 再算一遍几何 |

## 15. 验收标准（DoD）

1. 全区署 × 双执行器：区外无告警、区内有告警，**结果一致**。  
2. `alert.region` 为真实命中名或「全画面」。  
3. 推理性能无显著回退。  
4. **代码层面**：告警用区域几何仅存在于 `VIDEO/.../region_gate.py`（及对其唯一调用链）。  
5. RUNTIME / iot-sink **无**第二套告警区域判定。  
6. 一个开关 `REGION_GATE_ENABLED` 可全局旁路。  

---

## 16. 总结

v1.1 相对「多挂载点 + sink 兜底」方案的修正：

- **逻辑**：只有 VIDEO `RegionGate` 一处。  
- **收口**：只有 `AlertCandidateIngest` 一扇门。  
- **部署**：mini/edge/standard/full 只在 Gate **之后** 分叉运输与存储。  
- **执行器**：负责算得准、报得全；**不算区域告警**。  
- **sink**：负责布防与落库；**不算区域告警**。

这样区域检测才能在不同部署模式下真正生效，且永远不会再出现「两套逻辑、两种结果」。
