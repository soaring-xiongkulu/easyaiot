## Overview

EasyAIoT is deployed via **Docker containers and a unified install script**. The platform consists of base middleware and business modules: DEVICE, AI, VIDEO, WEB, APP, and RUNTIME.

| Module | Directory | Description |
|--------|-----------|-------------|
| Base services | `.scripts/docker` | Nacos, PostgreSQL, Redis, Kafka, MinIO, etc. |
| DEVICE | `DEVICE/` | Device management & API gateway (Java / Spring Cloud) |
| AI | `AI/` | Model training & inference (Python) |
| VIDEO | `VIDEO/` | Video streaming, alerts, recording (Python); may start RUNTIME for algorithm tasks |
| RUNTIME | `RUNTIME/` | C++ high-speed frame executor; mounted with VIDEO on center, or **atomic install-only** on compute nodes |
| WEB | `WEB/` | Management console (Vue 3) |
| APP | `APP/` | Mobile H5 (**full** profile only) |

**Unified entry scripts** (Linux x86 examples below):

| OS | Script |
|----|--------|
| Linux x86 | `.scripts/docker/install_linux.sh` |
| CentOS / RHEL family (x86) | `.scripts/docker/install_linux_centos.sh` |
| **CentOS / RHEL family · ARM** | `.scripts/docker/install_linux_centos_arm.sh` |
| **Kylin (麒麟)** | `.scripts/docker/install_linux_kylin.sh` |
| **openEuler (欧拉)** | `.scripts/docker/install_linux_openeuler.sh` |
| Linux ARM (generic) | `.scripts/docker/install_linux_arm.sh` |
| macOS | `.scripts/docker/install_mac.sh` |
| Windows | `.scripts/docker/install_windows.ps1` / `install_windows.sh` |

## Two Usage Modes

The unified entry script supports **interactive guidance** and **direct command** modes with identical underlying capabilities:

| | Interactive | Direct Command |
|---|---|---|
| **Entry** | No args / `menu` / `interactive` | `<command> [args]` |
| **Use case** | First deploy, on-site ops, troubleshooting | Dev, scripted ops, CI/CD |
| **Operation** | Menu-driven, numeric selection | Execute subcommand directly |
| **After execution** | Returns to current menu level | Exits when done |

```bash
# Interactive
sudo .scripts/docker/install_linux.sh

# Direct command
sudo .scripts/docker/install_linux.sh install
.scripts/docker/install_linux.sh status
```

**Selection guide:**

- Manual day-to-day ops, unfamiliar with command args → Interactive
- Known operation, scripting or cron jobs → Direct command (**do not** invoke without args in Cron/CI — it will block waiting for input)

### Interactive: Menu Structure

**Root menu**

```
  1) Deploy — install, start/stop, update, status, logs
  2) Analyze — log merge, disk usage, health checks
  0) Exit
```

**[Deploy] submenu**

| # | Action | Equivalent command |
|:-:|--------|-------------------|
| 1 | First install & start | `install` |
| 2 | Start all services | `start` |
| 3 | Stop all services | `stop` |
| 4 | Restart all services | `restart` |
| 5 | View status | `status` |
| 6 | View logs | `logs` |
| 7 | Health verification | `verify` |
| 8 | Update images & restart | `update` |
| 9 | Check Docker environment | `check` |
| 10 | View deploy profile | `profile` |
| 11 | Full CLI help | `help` |

**[Analyze] submenu**

| # | Action | Equivalent command |
|:-:|--------|-------------------|
| 1 | Multi-module log merge (~500 lines per source) | `analyze-logs` |
| 2 | Disk usage analysis | `analyze-disk` |
| 3 | Status + health verification | `status` + `verify` |
| 4 | Docker environment check | `check` |

**Typical paths:**

| Scenario | Interactive path |
|----------|-----------------|
| First deployment | 1 → 1 → 7 |
| Start after reboot | 1 → 2 → 7 |
| Collect diagnostics | 2 → 3 → 1 → 2 |

## Quick Start

Open the docs and mutter: “Can my little box even run this?” — **Yes. Don’t panic.**

Lightest tier **edge**, containers use about **1 GB** total. Cameras, real-time analysis, smart alerts—small machines still close the loop. Spin up that old laptop first; upgrade later when you’re hooked.

### Three steps (recommended)

```bash
git clone https://gitee.com/volara/easyaiot.git
cd easyaiot

# Option A (recommended)
EASYAIOT_DEPLOY_PROFILE=edge sudo bash .scripts/docker/install_linux.sh install

# Option B
# sudo bash .scripts/docker/install_linux.sh edge install
```

Then open `https://<server-ip>:8888` — default `admin` / `admin123`. Sanity-check:

```bash
.scripts/docker/install_linux.sh verify
# Optional: peek at memory vs the tier budget
.scripts/docker/install_linux.sh resources
```

All green? You’re done—easier than you feared. Go grab that coffee early.

> Need full profiles, interactive menus, or CentOS / ARM / openEuler entry scripts? Continue with Prerequisites and the two install options below.

### Prerequisites

- OS: **Ubuntu 24.04+** (26.04 recommended); also **CentOS/RHEL family** (incl. **CentOS ARM**), ARM, **Kylin (麒麟) / openEuler (欧拉)**
- Docker + Docker Compose **v2.35+** (on CentOS / CentOS ARM / **openEuler (欧拉)**, the OS-specific entry can install/upgrade Docker CE)
- **≥ 300 GB** free disk space (light **edge** can be far looser; reserve this for full tiers)

```bash
docker --version && docker compose version && docker ps
```

### Option 1: Interactive

```bash
git clone https://gitee.com/volara/easyaiot.git
cd easyaiot

# Ubuntu / generic Linux x86
sudo .scripts/docker/install_linux.sh

# CentOS / RHEL / Rocky / Alma x86 (recommended; Docker CE, mirror, firewalld)
# sudo .scripts/docker/install_linux_centos.sh

# CentOS / RHEL family ARM (recommended; then delegates to install_linux_arm.sh)
# sudo .scripts/docker/install_linux_centos_arm.sh

# openEuler (recommended; replace stock docker-engine, fix releasever, install Docker CE)
# sudo .scripts/docker/install_linux_openeuler.sh

# 1 Deploy → 1 First install → 7 Health verify
```

Profile (including **edge**) is selected interactively on first install. Open `https://<server-ip>:8888` when done (default `admin` / `admin123`).

### Option 2: Direct Command

```bash
git clone https://gitee.com/volara/easyaiot.git
cd easyaiot

# Optional: pull pre-built images to shorten install time
sudo .scripts/docker/install_linux.sh pull
# CentOS x86: sudo .scripts/docker/install_linux_centos.sh pull
# CentOS ARM: sudo .scripts/docker/install_linux_centos_arm.sh pull
# openEuler: sudo .scripts/docker/install_linux_openeuler.sh pull

sudo .scripts/docker/install_linux.sh install
# CentOS x86: sudo .scripts/docker/install_linux_centos.sh install
# CentOS ARM: sudo .scripts/docker/install_linux_centos_arm.sh install
# openEuler: sudo .scripts/docker/install_linux_openeuler.sh install

.scripts/docker/install_linux.sh verify
# CentOS x86: .scripts/docker/install_linux_centos.sh verify
# CentOS ARM: .scripts/docker/install_linux_centos_arm.sh verify
# openEuler: .scripts/docker/install_linux_openeuler.sh verify

# Optional: peek at memory vs the tier budget
.scripts/docker/install_linux.sh resources
```

Then open `https://<server-ip>:8888`. All green? You’re done—easier than you feared.

### CentOS / RHEL notes

Use `.scripts/docker/install_linux_centos.sh` on CentOS 7/8/Stream, Rocky, Alma, RHEL (x86). It upgrades stock docker 1.13 → Docker CE 20+, configures DaoCloud mirror and firewalld, then delegates to `install_linux.sh`. Docker only: `--upgrade-docker-only`. Details (ZH): [平台部署文档_zh.md § CentOS](./平台部署文档_zh.md#centos--rhel-系说明).

### CentOS / RHEL · ARM notes

Use `.scripts/docker/install_linux_centos_arm.sh` on aarch64/arm64 CentOS/RHEL family. Same Docker CE / mirror / firewalld prep as x86 CentOS, then delegates to `install_linux_arm.sh` (sets `DOCKER_PLATFORM=linux/arm64`). Docker only: `--upgrade-docker-only`. Details (ZH): [平台部署文档_zh.md § CentOS ARM](./平台部署文档_zh.md#centos--rhel-系--arm-说明).

### **openEuler (欧拉)** notes

Use `.scripts/docker/install_linux_openeuler.sh` on **openEuler (欧拉)** 24.03 LTS and other 24.x releases (x86_64 / aarch64). It removes conflicting stock `docker-engine`, rewrites Docker CE repo `$releasever` (default el9, fallback `--el-release 7`), configures DaoCloud mirror + DNS and firewalld, then delegates to `install_linux.sh`. Docker only: `--upgrade-docker-only`. Details (ZH): [平台部署文档_zh.md § **openEuler (欧拉)**](./平台部署文档_zh.md#openeuler-24x-说明).

### Install Duration

| Scenario | Estimated time |
|----------|---------------|
| Pre-built images pulled | 10–30 minutes |
| Full local build | 30 minutes to several hours |

`install` flow: select profile → env check → create network → deploy middleware & modules → health wait. See [One-Click & Step-by-Step Deployment](./部署最佳实践_en.md#one-click--step-by-step-deployment).

## macOS / Windows Image-Only Deploy

Desktop platforms (**macOS**, **Windows**) support **pre-built image deployment only**. Local `docker build` / `build-runtime` are rejected. Use Linux CI/servers to build and push images.

| Platform | Entry script | Notes |
|----------|--------------|-------|
| macOS | `.scripts/docker/install_mac.sh` | Docker Desktop; bash 4+ (`brew install bash`) |
| Windows | `.scripts/docker/install_windows.ps1` | PowerShell launcher → Git Bash / WSL |
| Windows | `.scripts/docker/install_windows.sh` | Run directly in Git Bash / WSL |

Details: [macOS guide](./平台macOS部署文档.md), [Windows guide](./平台Windows部署文档.md). Chinese: [macOS](./平台macOS部署文档_zh.md), [Windows](./平台Windows部署文档_zh.md).

### Prerequisites

- Docker Desktop running
- Repository cloned (compose + scripts; runtime artifacts come from the registry)
- macOS: Homebrew bash 4+
- Windows: Git for Windows or WSL; WSL2 backend recommended
- Configure `registry-mirrors` in Docker Desktop → Settings → Docker Engine

### Quick install

```bash
# macOS
bash .scripts/docker/install_mac.sh pull
bash .scripts/docker/install_mac.sh install
bash .scripts/docker/install_mac.sh verify
```

```powershell
# Windows PowerShell
.\.scripts\docker\install_windows.ps1 pull
.\.scripts\docker\install_windows.ps1 install
.\.scripts\docker\install_windows.ps1 verify
```

Unsupported on desktop: `build`, `build-runtime`, `clean-build-runtime`.

Access locally at `https://localhost:8888`.

## Deployment Profiles

Selected interactively on first `install`, saved to `.scripts/docker/.deploy_profile`. Reused by subsequent `start` / `stop` / `update`.

| Option | Name | Recommended RAM | Use case |
|:------:|------|-----------------|----------|
| 0 | **edge** | ≥ 2 GB | Lightest edge / old box trial (see [Quick Start](#quick-start)) |
| 1 | **mini** | ≥ 8 GB | Edge nodes, PoC |
| 2 | **standard** | ≥ 16 GB | Regular production |
| 3 | **full** (default) | ≥ 20 GB | Full features + APP H5 |

```bash
.scripts/docker/install_linux.sh profile                              # View current profile
export EASYAIOT_DEPLOY_PROFILE=full && sudo .../install_linux.sh install  # Non-interactive
```

Profile service differences: [Deployment Profile Selection](./部署最佳实践_en.md#deployment-profile-selection).

## RUNTIME Atomic Mode (Compute Nodes)

For **edge boxes / cluster workers**: install **only** the C++ executor—no local VIDEO / WEB / DEVICE. Alerts and heartbeats aggregate to center VIDEO; formal `realtime` tasks still default-push boxed detection streams to center/cluster SRS `ai/`.

> **Atomic ≠ never push video.** Atomic only means no local business stack. Details: [`RUNTIME/README.md`](../../RUNTIME/README.md).

```bash
# Top-level entry (recommended)
VIDEO_BASE_URL=http://<center-VIDEO>:6000 \
  bash .scripts/docker/install_linux.sh runtime

# Module entry
VIDEO_BASE_URL=http://192.168.1.10:6000 ./RUNTIME/install_linux.sh atomic
```

| Item | Notes |
|------|-------|
| Required | `VIDEO_BASE_URL` (or pass as arg), e.g. `http://192.168.1.10:6000` |
| Install dir | Default `/opt/easyaiot/RUNTIME` (`EASYAIOT_RUNTIME_INSTALL_DIR`) |
| Outputs | `bin/RUNTIME`, `node.env`, `env.sh`, `config/atomic.example.ini` |
| Formal tasks | Create algorithm tasks on center WEB (`executor=cpp`); VIDEO + Agent deploy ini |
| Smoke test | `source /opt/easyaiot/RUNTIME/env.sh && $RUNTIME_BIN …/atomic.example.ini` |
| Batch | WEB “workload distribute” → RUNTIME(C++) |

Center full-stack still uses `install`; local VIDEO install auto-builds/mounts RUNTIME via `ensure_runtime_cpp.sh`—different from atomic mode.

## FAQ

| Symptom | Resolution |
|---------|------------|
| Docker `permission denied` | `sudo usermod -aG docker $USER && newgrp docker` |
| Compose version too old | `sudo apt install -y docker-compose-plugin` |
| Port in use | `ss -tlnp \| grep <port>` |
| Install failed | `tail .scripts/docker/logs/install_linux_*.log` |
| Services up but unreachable | `verify` + check firewall |
| Insufficient disk | `df -h /`, reserve ≥ 300 GB |

**Collect diagnostics:**

```bash
# Interactive: 2 Analyze → 1 Logs + 2 Disk
# Direct command:
.scripts/docker/install_linux.sh check
.scripts/docker/install_linux.sh status
.scripts/docker/install_linux.sh verify
cd .scripts/docker && ./analyze_merge_logs.sh --non-interactive --modules all --save
./analyze_disk_usage.sh --save
```

More: [Troubleshooting](./部署最佳实践_en.md#troubleshooting).

## Environment Requirements

| Item | Requirement |
|------|-------------|
| OS | Ubuntu 24.04+ (26.04 recommended); also macOS, Windows, CentOS/RHEL, ARM, **Kylin (麒麟) / openEuler (欧拉)** |
| CPU | Min. 4 cores, 8+ recommended |
| RAM | Depends on profile (full ≥ 20 GB, 32 GB recommended) |
| Disk | Min. 300 GB free, 500 GB+ SSD recommended |
| GPU | Optional; NVIDIA GPU (CUDA 12.8) for AI training/inference |
| Docker Compose | v2.35.0+ |

```bash
# Docker install (Ubuntu)
curl -fsSL https://get.docker.com | sudo sh
sudo apt install -y docker-compose-plugin
sudo usermod -aG docker $USER && newgrp docker
```

**Notes:**

1. Use `sudo` on first install (mirror acceleration & RTP port reservation)
2. Change default middleware passwords in production ([credentials](./部署最佳实践_en.md#default-credentials))
3. `clean` deletes volumes — back up first
4. Rebuild WEB after profile change: `cd WEB && ./install_linux.sh build`
