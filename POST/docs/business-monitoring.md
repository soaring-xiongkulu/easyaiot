# 后处理业务监测

## 用户入口

先保存算法任务及关联摄像头并开启告警事件。在任务卡片点击可见文字「配置线 / 区域与规则」，或从任务表单「监测规则」打开同一个工作区。

1. 选择摄像头，等待基准画面加载。选择「检测线」并从 A 拖到 B，松开后自动保存；矩形拖拽绘制，多边形依次点选顶点、双击完成。
2. 点击图形或右侧列表选中它。线显示 A/B、正向绿色箭头，可拖动端点或交换 A/B。区域列表和画面标签直接显示绑定的业务规则。
3. 在右侧「规则设置」中，检测线绑定人流/越线；矩形、多边形选择区域进出、人员聚集或逗留。设置参数后点击「建立绑定」。规则独立保存，有保存/同步状态提示；无需再次提交任务表单。
4. 在同一面板点击「统计反馈」，查看当前图形自己的穿越方向、进出次数、逗留提醒、人数触发记录和最近事件。更换图形会切换统计范围，支持手动刷新。

产品取舍：监测工作区是唯一业务配置入口。任务表单已退出旧串行编排抽屉，并且提交表单不会覆盖工作区规则。底层扩展插件、调试及历史规则结构保留。

越线、进出和停留场景目前使用 **Python 实时算法 + 目标追踪**。每个摄像头需要在区域配置中绘制检测线或多边形。人流场景默认目标类别为 `person`，使用其他类别名称的模型需要修改参数。区域支持运行时更新。

任务卡片和表格操作中的「后处理业务看板」提供跨图形的汇总和事件明细，按日期、摄像头、插件查询。工作区内的反馈进一步按 `region_id` 严格筛选。日期按浏览器所在时区转换成 UTC 查询；默认查看当天。

## 执行与统计口径

- 越线方向：按线起点→终点，左侧到右侧为正向，反之为反向；压线中间帧不会清除先前方向。只统计穿过绘制线段的运动。
- 轨迹插件需要区域外观测，因此首部区域过滤将空间判断交给越线、进出或停留插件。缺少对应几何区域时不产生业务告警。
- 连续业务插件在 Python 生产者侧跳过告警抑制，先处理观测。人数插件支持 `cooldown_sec`，聚集场景默认 60 秒；逗留事件每个目标每次进入只触发一次，离开后重置。
- 显式绑定保存在插件参数 `region_ids` 中。同一插件可分别绑定多条线或多个区域，并分别设置参数、暂停、解除关联。每个绑定从完整的本帧观测独立执行，未触发的一条规则不阻断其他规则；同帧触发结果合并入库，`enrichment.business_rules` 保留每个区域的独立结果。
- 首次保存绑定时，将旧空间插件的隐式范围展开到原本适用的各图形，保留其他摄像头、参数及启停状态。界面会提示这次语义迁移。未迁移的历史任务继续原有串行语义。删除图形会在同一数据库事务中清理其绑定。
- 绑定与图形编辑共用 `template_revision`，保存时检查版本，防止互相覆盖。看板只统计成功触发并入库的告警，非原始推理帧或被过滤的事件。
- 迁移后的任务使用 `default_pass.params.monitoring_mode=bound` 标记。暂停或删除最后一条规则不会退化为全画面直接告警；无触发规则就不产生监测告警。旧全画面人数规则迁移后须核对图形范围，缺少可用图形的旧规则保留参数并暂停。
- 人流数为穿越次数，往返会重复累计，不表示去重访客或当前在场人数。历史旧事件方向为 `both` 时只计总次数，不推测方向。
- 人数峰值仅来自触发记录；会受阈值及提醒间隔影响，不能视为持续占用人数峰值。
- 区域「离开」包含两类：目标被观测到走出区域的正常离开，以及目标消失后超过 `exit_timeout_sec`（默认 15 秒，`region_enter_exit` 参数可调）由 POST 合成补记的离开，合成事件在 `enrichment` 中带 `synthesized: true`。两类都计入离开次数，保证进入/离开最终趋于平衡。

## API

`GET /video/post/tasks/{task_id}/results`

参数：`start`、`end`（带时区 ISO 时间，左闭右开，最多 31 天）、`page`（默认 1）、`page_size`（1~100，默认 20）、可选 `device_id`、`region_id` 与 `plugin`。

返回标准 `{code,msg,data}`；`data` 包含 `items`、`total`、`summary`、分页和 UTC 查询范围。读取现有 `alert.information.enrichment`，无需新增数据库表。

`GET /video/post/tasks/{task_id}/bindings` 获取任务规则、图形关联、前置条件和版本。`PUT /video/post/tasks/{task_id}/regions/{region_id}/binding` 保存/暂停/解除单个绑定；请求携带 `expected_revision`、`plugin`、`params`、`enabled` 或 `remove`。校验区域归属、几何类型和运行前提后，提交配置并热更新运行模板。

## 当前边界与部署验证

C++ 执行器目前仍输出 `track_id=0`，连续轨迹插件会在配置时提示改用 Python 实时模式。业务脚本/姿态分析走独立 sink 路径，暂不支持与连续轨迹插件混用，前后端都会明确拦截。外置插件仍使用现有登记与编排入口，本看板当前呈现四类内置业务结果。

POST 轨迹及提醒状态存放于单进程内存，重启会重置。多副本部署须保证同一任务/摄像头的观测进入同一副本；此变更未引入跨副本共享状态。

### track_id 稳定性（2026-10 修复）

同一人反复检测得到不同 `track_id` 会导致重复计数、离开人数缺失，修复分三层：

1. **VIDEO 追踪器**：`SimpleTracker` 的 `leave_time_threshold` 默认从 0.5 秒提高到 5 秒（该值必须大于推理采样间隔，否则连续两帧漏检即删轨迹换新 ID）；可用环境变量 `TRACKING_LEAVE_TIME_THRESHOLD` 覆盖（下限 1 秒）。生产者按设备惰性创建追踪器，缺失时不再静默回退 `track_id=0`。
2. **VIDEO 空帧心跳**：需要连续观测的任务在检测为空时也周期（`POST_KEEPALIVE_INTERVAL`，默认 5 秒）发布空检测 InferEvent（`hints.keepalive=true`），驱动 POST 状态过期检查，避免画面清空后离开事件永远缺失。
3. **POST 合成离开**：`region_enter_exit` 对超过 `exit_timeout_sec` 仍在区域内的轨迹合成 exit 事件（带 `synthesized: true`），并重放最后观测以便分支通过空检测门禁。单测 `TestRegionEnterExitSynthesizesExitAfterTrackVanishes` 覆盖。

### 业务脚本 IDE 入口（2026-10 修复）

`FrameDynamic.vue` 此前因 Node-RED 引入的 `flowId = code || index` 回归，把任务 ID 拼进 `/dev-api/vscode/{taskId}` 导致业务脚本编辑器 404。现已恢复 `?folder=` 优先拼接，Node-RED 无 folder 参数不受影响。

发布需更新 WEB、VIDEO、POST。现场验收：确认 MQTT 推理事件连续携带稳定的正整数 `track_id`；人员从检测线两侧分别通过，检查方向记录；进入后离开区域，检查进出事件；停留超过阈值，确认一次提醒；人员聚集超过阈值，确认提醒间隔；最后在业务看板按摄像头核对入库记录。

本地已覆盖 POST 单元测试、Python 参数/查询测试及 Vue 模板编译。`test_post_fail_strategy_contract` 已按 C++ 当前中文日志文本校准，生产者 fail-open/fail-closed 四项契约全部通过。

### 隔离回归环境（2026-10-28 已跑通）

`POST/tools/regression-broker`（mochi-mqtt :18883）+ POST（:19090，`POST_DEBUG=true`）+ `VIDEO/tools/monitoring_regression_server.py`（默认 :6000，真实 blueprint 与 SQLite 夹具）+ `WEB/vite.regression.config.ts`（默认 :8888，入口 `/monitoring-regression.html`）组成全链路回归：浏览器画线/矩形 → 绑定越线/进出/聚集/逗留 → 测试面板经真实 MQTT 发布追踪帧 → POST 引擎 → 告警入库 → 统计反馈与业务看板对账。VIDEO 工作目录、VIDEO 端口、WEB 端口和代理目标均可用 `MONITORING_REGRESSION_*` 环境变量覆盖，便于与已运行的生产容器并行。本轮已验证：越线正反向、区域进出、聚集峰值、逗留 1 秒触发、版本冲突（提示+重载保留/放弃编辑）、保存 503（报错保留编辑可重试）、区域与线统计文案分版。

### 训练场模式（2026-10-28 新增；同日移植生产链路）

监测规则工作区顶部「训练场模式」开关：不依赖真实摄像头，在训练场景地图上**放置、拖动模拟人**验证插件触发逻辑。地图以归一化坐标叠加当前摄像头已绘制的线与区域，与画布图形实时同步。

- 生产链路：投放走 `POST /video/post/tasks/{id}/trainframe`（VIDEO 生产 blueprint，`app/services/train_frame_simulator.py`）——复用生产 `build_infer_event` + `publish_infer_event` 经真实 MQTT `mqtt/iot-infer-event` 驱动 POST 引擎，与真实推理帧同一条链路；隔离回归 mock 注册同一 blueprint，两端行为一致。

- 交互：点击地图空白放置模拟人（自动编号），按住拖动改变位置；拖入多边形时该区域高亮，直观显示命中判定。
- 投放：手动「投放一帧」或「启动投放」按 0.5/1/2 秒间隔持续投放。每个投放帧携带全部模拟人（`track_id = 9000000 + 编号`，跨帧稳定，天然验证轨迹逻辑），经 mock 的 `POST /video/regression/trainframe` 走真实 MQTT 进入 POST 引擎。
- 计数器：越线（正/反）、区域进入/离开（含超时补记）、人数峰值、逗留提醒，数据直接来自业务结果 API；「最近触发」日志实时列出每条入库事件，覆盖全部五类事件语义：进入/离开（区分超时补记）、正向/反向越线、逗留时长、聚集人数（含阈值），标签颜色按语义区分（绿=正向/进入、红=反向/离开、橙=逗留、紫=聚集）。
- UI（2026-10-28 二次优化）：训练场面板改用项目封装组件（`@/components/Button`、`@/components/Icon`），地图含网格底纹、A/B 端点与正向箭头、拖动尾迹、图例；工作区顶部说明条改为数字徽章分步指引（选择摄像头画图形 → 绑定规则 → 查看统计）。训练场入口在生产监测工作区与隔离回归环境使用同一组件和同一生产 `trainframe` 路由。
- 已验证：拖人越线（正向）与拖动路径顺带穿线（反向，路径物理连续即计数）、拖入/拖出区域（真实进出）、多人聚集（6 人进区+峰值）、持续投放触发逗留、超时补记离开自动出现。
- 注意：模拟人须处于图形感知范围内（线段 x 区间且距线约 0.12 内 / 多边形内部）投放帧才会进入插件，站在空地上的帧会被前置过滤丢弃。服务端按 120 秒窗口节流重推 POST 任务模板（缓存为滑动 TTL，持续投放时每帧自动续期），长期空闲后首帧也不会 `task_cache_miss`。
- 模拟数据口径：模拟目标固定使用 `track_id` 9,000,000~9,999,999 段（服务端强校验），与真实轨迹天然可区分；模拟事件会与真实告警一样写入业务结果（同任务同设备的当日统计会包含模拟数据）。若需要统计默认排除模拟数据，可在结果聚合层按 track_id 段过滤（后续可选项）。
