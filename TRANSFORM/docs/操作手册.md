# 运行手册

> 目标：用最少命令完成「本机默认 + 业务流程 + 旁路扩容 + 分发压测」。

---

## 0. 发布前回归（3 条命令）

```bash
# 1) 本机默认链路（本机没有也会自动拉起）
cd /projects/new/easyaiot/TRANSFORM/scripts/test-pipeline
bash run_all.sh --mode full --count 1

# 2) 本机 + 旁路扩容（推荐每次发布都跑）
bash run_all.sh --mode full --count 2

# 3) 分发/镜像链路（docker 构建+load+心跳验收）
cd /projects/new/easyaiot/TRANSFORM
bash scripts/pipeline-distribute-run.sh --mode local --count 2
```

通过标准：

- 日志出现 `OK PIPELINE TEST PASSED`
- 业务验证出现 `01 PASS: kafka/http/party 多渠道已打通`
- 分发链路出现 `PIPELINE_OK`

## 1. 一键全流程（本机没有也能跑）

```bash
cd /projects/new/easyaiot/TRANSFORM/scripts/test-pipeline
cp -n env.example .env
bash run_all.sh
```

等价便捷入口（在 `TRANSFORM/scripts` 目录下）：

```bash
cd /projects/new/easyaiot/TRANSFORM/scripts
./test_full_pipeline.sh
```

再等价（仓库根目录）：

```bash
bash TRANSFORM/scripts/test_full_pipeline.sh
```

这条会自动做：

- 预检 Kafka / PG / Topic / jar
- 本机 `:48096` 没有就自动拉起 TRANSFORM
- mock 接收端（MES/ERP/WMS）没有就自动拉起
- 心跳 + 集群 API + PING
- 业务投喂并断言：
  - `iot_device_message -> party-erp`
  - `iot-alert-notification -> party-mes + http-webhook`
  - `iot-face-matching -> party-wms`

---

## 2. `--count 2` 怎么理解

在 `run_all.sh`（full 模式）里：

- `--count 1`：只验证本机默认实例
- `--count 2`：本机默认 + 1 个旁路实例（`48110+`）
- `--count N`：本机默认 + `N-1` 个旁路实例

示例：

```bash
bash run_all.sh --mode full --count 2
```

## 3. 常用命令（直接抄）

```bash
# 只跑本机默认（不扩容）
bash run_all.sh --mode full --count 1

# 本机 + 旁路 1 个
bash run_all.sh --mode full --count 2

# 只验部署/心跳，不跑业务投喂
bash run_all.sh --skip-business

# 跑完也关掉“脚本自动拉起”的本机默认实例
bash run_all.sh --cleanup-local

# 保留所有测试进程（用于排查）
bash run_all.sh --no-cleanup
```
